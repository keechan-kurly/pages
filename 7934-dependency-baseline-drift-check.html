PR CI 흐름 변경: 유닛 테스트 앞에 전이 의존성 drift 검사

storeRelease 런타임 전이 의존성을 baseline 파일(app/dependencies-snapshot.txt, 425개 좌표)로 고정하고, PR CI 는 오래 걸리는 유닛 테스트보다 먼저 drift 를 검사해 fail-fast 한다. 주석에 적힌 목적은 시간 절약이다.

drift 는 의도된 변경인지 CI 가 판별할 수 없어서 자동 수정하지 않고 워크플로를 실패시킨다. 의도된 변경이면 개발자가 PR 에 /apply-dependencies 코멘트를 남겨 baseline 갱신을 요청한다.

추론: KMA-8359(라이브러리 버전 최신화) 과정에서 의도치 않은 전이 의존성 유입을 PR 단계에서 드러내려는 목적으로 보인다. PR 본문에 목적 설명은 없다.
