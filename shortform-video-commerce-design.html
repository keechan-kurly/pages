사용자 여정 — 홈 숏폼 진입에서 PDP 왕복까지

사용자 인터랙션이 트리거인 신규 흐름이다. 홈 썸네일 탭 한 번으로 홈을 덮는 세로 풀스크린 플레이어가 열리고, 세로 스와이프로 영상이 이어지며, 상품 태그로 PDP를 오가는 동안 플레이어 인스턴스는 살아 있어 재생 위치가 유지된다. 오른쪽 Mock은 각 스텝과 12초 루프로 동기화된다.

1
홈 숏폼 섹션 노출 + 신규
정적 썸네일 8~10개를 가로 스크롤로 노출, 뷰포트 진입 시 노출 로깅
LazyRow · Modifier.onImpression()
main/v3 sections 체계 → 썸네일 카드 리스트
2
카드 탭 → 플레이어 진입 NEW Activity
진입 즉시 자동재생·기본 mute. 썸네일 URL 동봉 시 첫 프레임 즉시 표시. 탭한 영상이 피드 선두
ShortFormPlayerActivity ← extras{ startVideoId }

3
세로 스와이프 연속 재생 + 신규
settledPage 기준으로 활성 페이지 전환, 전환 시 시청 이벤트 fire-and-forget 전송

페이지 전환 → (videoId, watchedMs, isCompleted)
4
상품 태그 탭 → PDP → 이동
영상당 태그 2~3개. 동일 task 스택으로 PDP 진입, PDP 위에서 플레이어는 pause(백그라운드 오디오 금지)
kurlyNavigator.navigate(ProductDetail(productNo))

5
뒤로가기 → 플레이어 복귀 + 신규

Activity.onRestart() · 재생 위치 유지
onRestart → resume(seekPos 유지) / X → finish()

Clean Architecture 레이어 배치

별도 모듈 신설 없이 기존 domain / data / features 구조에 숏폼 컴포넌트를 얹는다. 순수 Kotlin 도메인을 중심(center)에 두고, Data는 인터페이스를 구현(하향)하고 Features는 UseCase에 의존(상향)해 양쪽 화살표가 Domain으로 수렴한다.

Network + 신규
+ ShortFormService — GET /shortform/feed, 좋아요 토글, POST /shortform/watch
홈 섹션 데이터는 기존 MainHomeService에 편입
↓ 응답 DTO
Data + 신규
+ DTO (전 필드 nullable · @SerializedName) · Mapper (방어적 변환)
+ ShortFormRepositoryImpl · SectionMapper 확장
↓ implements (인터페이스 구현)
Domain CENTER · 순수 Kotlin
Model — ShortFormVideo · ShortFormProduct · ShortFormFeedPage
Repository — ShortFormRepository (interface)
UseCase — GetShortFormFeed · ToggleShortFormLike · ReportShortFormWatch
↑ depends on (UseCase 의존)
Features + shortform/
+ ShortFormPlayerActivity (BaseActivity · portrait 고정 · 검정 풀스크린)
+ ShortFormPlayerCore 단일 영상 코어 — PDP 재사용 경계 + ShortFormFeedScreen VerticalPager 피드 컨테이너
App / Home ~ 기존 체인에 값 추가
~ 서버 driven 섹션 체인 그대로: SectionDesignType 신규 값 → TemplateCode → MainSection 모델 → SectionMapper → ComposeView ViewHolder 등록 (참조: NoticeBannerSectionViewHolder)
왜 이 구조인가
"홈을 덮는 모달" 요구 → 표준 Activity 스택(A안 네이티브 신규 구축)을 채택했다. 라이브커머스(Grip WebView)는 플레이어 재사용이 불가해 UI 셸 참고용으로만 남는다.
Core / Container를 분리한 이유는 PDP 플레이어 재사용(가정 A2)에 대비해 재사용 경계를 미리 확보하기 위함이다.

기술 코어 — 플레이어 풀 · HLS 파이프라인 · 낙관적 업데이트

끊김 없는 세로 스와이프의 핵심은 현재±1 플레이어 풀(총 3개)과 SimpleCache 조합이다. 아래 미니어처는 세로 피드 안에서 풀이 어떻게 움직이는지, HLS 스트림이 화면에 닿는 경로, 좋아요 탭이 갈라지는 두 경로를 보여준다.

+ 신규 플레이어 풀 — 세로 피드에서 현재±1만 준비한다
↑ 스와이프 ↓
이전 영상 (−1)대기
prepare()만 — 초기 세그먼트 버퍼링
▶ 현재 영상재생 중
유일하게 재생되는 플레이어 — 소리·진행 모두 여기서만
다음 영상 (+1)대기
prepare()만 — 초기 세그먼트 버퍼링
1. 스와이프가 멎으면 창이 한 칸 이동한다
새로 이웃이 된 페이지만 prepare(), 멀어진 플레이어는 회수해 재사용
2. 이웃은 소리 없이 버퍼만 채운다
playWhenReady = false — 스와이프 순간 끊김 없이 즉시 재생되는 이유
3. 재시청은 네트워크 없이 캐시로
세그먼트가 SimpleCache(100MB LRU)를 거쳐 저장 — 재시청·재순환 대응
저사양 단말인 경우 ~→ 풀 3개 → 1개(현재만)로 다운시프트
- PreloadManager 는 Media3 1.4.1 기준 불안정 API라 기각 — 위 풀 + 캐시 조합이 그 자리를 대신한다.
+ 신규 HLS 파이프라인 — URL이 화면에 닿기까지
